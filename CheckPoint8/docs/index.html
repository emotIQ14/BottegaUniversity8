1 ¿Qué tipos de bucles hay en JavaScript?

Los bucles (o loops) son estructuras de control que ejecutan un bloque de código repetidamente mientras se cumpla una condición. Son fundamentales para automatizar tareas que de otra forma habría que escribir decenas o miles de veces.

💡 Imagina tener que saludar a 100 personas. Sin bucles, escribirías console.log("Hola") cien veces. Con un bucle, lo haces en 3 líneas.

Los 6 tipos principales

1. for

Cuando sabes cuántas veces quieres iterar.

for (let i = 0; i < 5; i++) {
  console.log(i);
}
// 0, 1, 2, 3, 4

2. while

Mientras la condición sea verdadera.

let n = 0;
while (n < 3) {
  console.log(n);
  n++;
}
// 0, 1, 2

3. do...while

Igual que while, pero se ejecuta al menos una vez.

let n = 0;
do {
  console.log(n);
  n++;
} while (n < 3);

4. for...of

Recorre los valores de iterables (arrays, strings...).

const arr = ["a", "b", "c"];
for (const v of arr) {
  console.log(v);
}

5. for...in

Recorre las claves de un objeto.

const obj = { a: 1, b: 2 };
for (const k in obj) {
  console.log(k, obj[k]);
}

6. forEach()

Método de array que itera de forma funcional.

["a", "b", "c"].forEach(
  (v, i) => console.log(i, v)
);

2 Diferencias entre const, let y var

JavaScript ofrece tres formas de declarar variables. Aunque parecen similares, tienen comportamientos muy diferentes que afectan al scope, reasignación y hoisting.

🕰️ var

La forma antigua (1997). Scope de función, se puede reasignar y redeclarar. Hoy en día se considera obsoleta.

var x = 1;
var x = 2; // OK pero peligroso

✏️ let

Moderna (ES6, 2015). Scope de bloque. Se reasigna pero no se redeclara. Para variables que cambian.

let edad = 28;
edad = 29; // OK

🔒 const

Constantes (ES6). Scope de bloque. No se puede reasignar. Tu primera opción siempre.

const PI = 3.14;
// PI = 3.15; ❌ Error

El concepto del scope (alcance)

function ejemplo() {
  if (true) {
    var a = 1;   // scope de función
    let b = 2;   // scope de bloque
    const c = 3; // scope de bloque
  }
  console.log(a); // ✅ 1
  console.log(b); // ❌ ReferenceError
  console.log(c); // ❌ ReferenceError
}

Bug clásico con var

// Con var (problema)
for (var i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 100);
}
// Imprime: 3, 3, 3 ¡no 0, 1, 2!

// Con let (correcto)
for (let i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 100);
}
// Imprime: 0, 1, 2 ✅

3 ¿Qué es una función de flecha?

Las funciones de flecha (arrow functions) son una sintaxis más corta y moderna para crear funciones, introducida en ES6 (2015). Usan el operador => y son ahora una de las características más utilizadas del lenguaje.

Comparación rápida

// Función tradicional
function saludar(nombre) {
  return "Hola " + nombre;
}

// Función de flecha equivalente
const saludar = (nombre) => "Hola " + nombre;

Variantes de sintaxis

Sin parámetros

const saludar = () => "¡Hola!";

Un parámetro

const cuadrado = x => x * x;

Varios parámetros

const sumar = (a, b) => a + b;

Cuerpo con varias líneas

const calc = (p, iva) => {
  const t = p * (1 + iva);
  return t.toFixed(2);
};

Características clave

  • ✅ Retorno implícito si el cuerpo es una sola expresión.
  • 🔗 No tienen this propio: heredan el del scope donde se definen.
  • 🚫 No pueden usarse como constructores (no se les puede llamar con new).
  • 📦 No tienen el objeto arguments.

Caso de uso real: métodos de array

const numeros = [1, 2, 3, 4, 5];

const duplicados = numeros.map(n => n * 2);
// [2, 4, 6, 8, 10]

const pares = numeros.filter(n => n % 2 === 0);
// [2, 4]

const suma = numeros.reduce((acc, n) => acc + n, 0);
// 15
⚠️ No las uses como métodos de objeto: como heredan el this, no podrán acceder al objeto contenedor.

4 ¿Qué es la deconstrucción de variables?

El destructuring (o deconstrucción) es una característica de ES6 que permite extraer valores de arrays u objetos y asignarlos a variables en una sola línea, de forma elegante y legible.

Antes vs. después

// SIN destructuring (forma antigua)
const persona = { nombre: "Ander", edad: 28 };
const nombre = persona.nombre;
const edad = persona.edad;

// CON destructuring (forma moderna)
const { nombre, edad } = persona;

Destructuring de objetos

const usuario = { nombre: "Ander", email: "a@b.com" };

// Básico
const { nombre, email } = usuario;

// Renombrar
const { nombre: nombreUsuario } = usuario;

// Valor por defecto
const { idioma = "es" } = usuario;

// Anidado
const { direccion: { ciudad } } = empresa;

Destructuring de arrays

const colores = ["rojo", "verde", "azul"];

// Básico (por posición)
const [a, b, c] = colores;

// Saltar elementos
const [primero, , tercero] = colores;

// Con rest
const [primero, ...resto] = colores;
// resto = ["verde", "azul"]

// Intercambiar variables
let x = 1, y = 2;
[x, y] = [y, x];

En parámetros de función (super útil)

function crearUsuario({ nombre, email, edad = 18 }) {
  console.log(nombre, email, edad);
}

crearUsuario({ nombre: "Ander", email: "a@b.com" });
// "Ander" "a@b.com" 18

5 ¿Qué hace el operador de extensión?

El operador de extensión (spread operator), escrito con tres puntos ..., sirve para expandir los elementos de un iterable (array, objeto, string) donde se esperan múltiples elementos.

Ejemplo introductorio

const numeros = [1, 2, 3];
console.log(numeros);    // [1, 2, 3]
console.log(...numeros); // 1 2 3

Casos de uso principales

📋 Copiar arrays

const copia = [...original];

🔗 Combinar arrays

const todo = [...a, ...b];

📦 Copiar objetos

const copia = { ...obj };

🔧 Combinar y sobrescribir

const nuevo = { ...obj, edad: 29 };

📞 Pasar como argumentos

Math.max(...numeros);

🔄 Eliminar duplicados

[...new Set(arr)];

Spread vs. Rest (NO confundir)

SpreadRest
PropósitoExpandeAgrupa
PosiciónEn llamadas / construcciónEn parámetros / destructuring
Ejemplofn(...arr)function fn(...args) {}
💡 Truco mnemotécnico: a la derecha del igual o en una llamada → spread. A la izquierda del igual o en parámetros → rest.

6 ¿Qué es la programación orientada a objetos?

La Programación Orientada a Objetos (POO) es un paradigma que organiza el código en torno a objetos que combinan datos (atributos) y comportamiento (métodos), modelando entidades del mundo real.

Los 4 pilares de la POO

🔒 Encapsulamiento

Proteger los datos de un objeto, exponiendo solo lo necesario. En JS se usa # para propiedades privadas.

🧬 Herencia

Una clase hereda atributos y métodos de otra. Se usa extends y super.

🎭 Polimorfismo

Distintos objetos pueden responder al mismo método de formas diferentes.

🎯 Abstracción

Esconder los detalles complejos, exponer solo lo importante.

Sintaxis de clases en ES6

class Persona {
  constructor(nombre, edad) {
    this.nombre = nombre;
    this.edad = edad;
  }

  saludar() {
    console.log(`Hola, soy ${this.nombre}`);
  }
}

const ander = new Persona("Ander", 28);
ander.saludar(); // "Hola, soy Ander"

Herencia con extends y super

class Animal {
  constructor(nombre) { this.nombre = nombre; }
  comer() { console.log(`${this.nombre} come`); }
}

class Perro extends Animal {
  ladrar() { console.log(`${this.nombre} ladra`); }
}

const rex = new Perro("Rex");
rex.comer();  // heredado
rex.ladrar(); // propio

7 ¿Qué es una promesa en JavaScript?

Una promesa es un objeto que representa el resultado eventual de una operación asíncrona. Es decir, una operación que tarda en completarse: una llamada a un servidor, leer un archivo, una espera...

Los 3 estados de una promesa

⏳ pending (pendiente)
↓
✅ fulfilled (cumplida)
o
❌ rejected (rechazada)

Crear una promesa

const promesa = new Promise((resolve, reject) => {
  const exito = true;
  if (exito) {
    resolve("¡Todo bien!");
  } else {
    reject("Algo falló");
  }
});

Consumir una promesa

fetch("https://api.example.com/datos")
  .then(respuesta => respuesta.json())
  .then(datos => console.log(datos))
  .catch(error => console.error(error))
  .finally(() => console.log("Termina sí o sí"));

El problema que resuelven: Callback Hell

// 😱 Sin promesas
pedirA(function(a) {
  pedirB(a, function(b) {
    pedirC(b, function(c) {
      pedirD(c, function(d) {
        // pirámide infinita
      });
    });
  });
});

// 🎉 Con promesas
pedirA()
  .then(pedirB)
  .then(pedirC)
  .then(pedirD)
  .then(resultado => console.log(resultado))
  .catch(err => console.error(err));

Métodos estáticos útiles

MétodoEspera a...Si una falla...

Promise.allSettledTodasDevuelve todos los resultados
Promise.raceLa primera (cumpla o falle)Depende
Promise.anyLa primera que cumplaSolo si todas fallan

8 ¿Qué hacen async y await?

async y await son palabras clave que simplifican enormemente el trabajo con promesas. Permiten escribir código asíncrono que parece síncrono: se lee de arriba abajo, como una receta paso a paso.

Comparación: .then() vs async/await

// Con .then() (promesas tradicionales)
function obtenerDatos() {
  return fetch("/api/usuarios")
    .then(res => res.json())
    .then(datos => {
      console.log(datos);
      return datos;
    });
}

// Con async/await (forma moderna)
async function obtenerDatos() {
  const res = await fetch("/api/usuarios");
  const datos = await res.json();
  console.log(datos);
  return datos;
}

¿Qué hacen exactamente?

  • async marca una función como asíncrona. Esa función siempre devuelve una promesa y permite usar await dentro.
  • await pausa la función async hasta que la promesa se resuelva, devolviendo el valor.

Manejo de errores con try/catch

async function obtenerUsuario(id) {
  try {
    const res = await fetch(`/api/usuarios/${id}`);
    if (!res.ok) throw new Error("Error HTTP");
    return await res.json();
  } catch (error) {
    console.error("Algo falló:", error.message);
    return null;
  }
}

⚡ Llamadas en paralelo con Promise.all

// ❌ Secuencial (lento: 6s)
const a = await fetch("/a"); // 2s
const b = await fetch("/b"); // 2s
const c = await fetch("/c"); // 2s

// ✅ Paralelo (rápido: 2s)
const [a, b, c] = await Promise.all([
  fetch("/a"),
  fetch("/b"),
  fetch("/c")
]);
💡 Importante: await no bloquea el hilo principal. Solo pausa la función async donde está. JavaScript sigue ejecutando otras tareas en paralelo.

Recordatorio rápido

  1. async hace que una función siempre devuelva una promesa.
  2. await solo funciona dentro de funciones async.
  3. Para errores → try/catch.
  4. Para llamadas independientes → Promise.all.
